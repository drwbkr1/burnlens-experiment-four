# Security policy

Do not report or test suspected vulnerabilities through experimental project
work. Avoid malformed-file probing, exploit construction, credential exposure,
or unapproved security testing.

Never commit credentials, tokens, cookies, account identifiers, private review
responses, or secret-bearing URLs. Use only separately approved secure custody
references when a later milestone requires authenticated access.

For repository security concerns, use GitHub's private vulnerability reporting
surface when available or contact the repository owner privately.
